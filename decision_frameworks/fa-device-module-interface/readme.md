# FA Device Module Interface Specification

## 概要

モーター・シリンダ・吸着パッド・検査機器など、  
FAデバイスの制御モジュールを共通I/Fで統一する仕様。

PLCopen Motion Control FBの思想をベースに、  
ログ・排他制御・上位連携を独自拡張。

---

## 設計思想

- デバイスの複雑さはモジュールに閉じ込める
- 上位は「要求」と「結果」だけ見ればいい
- ログの網羅性を制御の簡便さより優先する
- インターロック層は別設計（本仕様の対象外）

---

## I/Fワードマップ

### INPUT

| ワード | 内容 | 形式 |
|--------|------|------|
| IN0 | 要求ID（排他制御兼） | 数値 |
| IN1 | コマンド | 数値 |
| IN2 | 補助パラメータ | 数値 |
| IN3 | 起動要求 | 0/1 |

### OUTPUT

| ワード | 内容 | 形式 |
|--------|------|------|
| OUT0 | 応答ID＋占有状態 | 数値 |
| OUT1 | 現在/目標ポジション番号 | 数値 |
| OUT2 | アラームコード | 数値 |
| OUT3 | ステータスビット | ビット |

---

## OUT3 ステータスビット

| bit | 内容 |
|-----|------|
| bit0 | READY |
| bit1 | MOVING |
| bit2 | IN_POSITION |
| bit3 | ALARM |
| bit4 | HOMING_REQUIRED |
| bit5 | BUSY |
| bit6 | 予備 |
| bit7 | 予備 |

---

## コマンド定義

### モーター／サーボ

| 値 | 動作 | 完了待ち |
|----|------|---------|
| 1–99 | ポジション移動 | あり（完遂） |
| 101–199 | ポジション移動 | なし（起動のみ） |
| 200 | 停止位置チェック | あり |
| 201 | 原点復帰 | あり |
| 210 | JOG+ | なし |
| 211 | JOG- | なし |

### シリンダ

| 値 | 動作 |
|----|------|
| 1 | 戻り |
| 2 | 行き |
| 3 | フリー |

### 吸着パッド

| 値 | 動作 |
|----|------|
| 1 | 吸着 |
| 2 | 解放 |

---

## IN2 補助パラメータ（多態）

| IN1コマンド | IN2の意味 |
|------------|----------|
| JOG | 速度オーバーライド（%） |
| 起動のみ移動 | 加速度プロファイル番号 |
| デバッグ時 | ステップ指定 |

---

## ログ設計

### 記録タイミング

| タイミング | 記録内容 |
|-----------|---------|
| 起動要求エッジ | IN0, IN1, IN2, 時刻 |
| IN_POSITIONエッジ | OUT1, 完了時刻 |
| ALARMエッジ | OUT2, 時刻 |

### ログから取れる情報

- 不具合再現（アラーム前の操作列）
- 稼働分析（ポジション遷移・時間分布）
- 予兆検知（移動完了時間の統計変化）
- 操作証跡（誰がいつ何を命令したか）

---

## テキストログ基盤

### バッファ設計

- サイズ：100〜1000エントリ（設備毎に調整）
- 書き込み：イベント駆動、ptrのみ更新
- 読み出し：非同期でファイル書き込み
- 閾値：80%でサイクル停止

### 制御コマンド定義

バッファエントリにコマンドを埋め込むことで、
ログと制御を同一チャンネルで扱う。

| コマンド | 動作 |
|---------|------|
| FILE_ROTATE | ファイル名変更 |
| DISK_CHECK | 空き容量確認 |

## 上位連携

### MCプロトコル経由（推奨）


Python（PC側）
　↓ MCプロトコル
PLC内バッファ
　↓ 展開ロジック
デバイス制御
　↓
ログ回収 → Python解析


- 通信遅延はバッファが吸収
- リアルタイム保証はPLC内部
- AIからの入り口はPython側に用意

### PLC内部実行（オプション）

上位連携不要な設備向けに内部実行モードを提供。

## 設計判断の背景

- 資料は散逸する。コメントとログがサバイバルする。
- 複雑さはモジュールに閉じ込める。上位はシンプルに保つ。
- 価値の発現は2〜3年後。標準採用は3〜4年後。
- Keyenceで実証し、MCプロトコル経由で他PLCにも横展開可能。
